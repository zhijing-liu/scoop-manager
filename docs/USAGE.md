# 使用说明

本文档面向日常使用者，按「启动 → 首次引导 → 各页面操作 → 常见工作流」的顺序说明。

---

## 一、启动

### 双击 exe

直接双击 `scoop-manager.exe`，等待终端窗口出现访问地址后，浏览器会自动打开 <http://127.0.0.1:3000>。

- 端口被占用时会**自动改用下一个可用端口**，终端里会明确提示实际端口。
- 不想自动开浏览器：`scoop-manager.exe --no-open`
- 关闭程序：在终端窗口按 `Ctrl+C`。

### 源码启动

```bash
pnpm dev          # Bun
pnpm dev:node     # Node + tsx
```

### pm2 常驻

```bash
pnpm run build
pnpm run pm2:start
```

pm2 配置里已加 `--no-open`，避免每次重启弹浏览器。

### 挂在反向代理的子路径下

想把界面放在 `/scoop/` 之类的子路径：

```bash
# 代理「透传前缀」时（proxy_pass 末尾没有斜杠）
scoop-manager.exe --base-path /scoop
```

若代理是「剥离前缀」（`proxy_pass http://127.0.0.1:3000/;`），则让它带上请求头即可，无需启动参数：

```nginx
proxy_set_header X-Forwarded-Prefix /scoop;
```

两种配置的完整 nginx / Caddy 示例见 [README 的「部署到反向代理」](../README.md#部署到反向代理子路径)。
注意把 `proxy_buffering off;` 加上，否则实时日志会失去实时性。

## 二、首次引导

启动后程序会自动检测本机 Scoop。若**未检测到**，页面会弹出引导向导，提供两条路径：

### 1. 一键安装

调用官方安装脚本把 Scoop 安装到指定目录。

- **安装目录**：留空则使用默认目录 `%USERPROFILE%\scoop`；也可以填 `C:\scoop` 等自定义路径，目录无需预先创建。
- **以管理员身份安装**：只有需要安装到 `C:\ProgramData` 等受保护位置时才勾选，会弹出 UAC 提示。
- 点击「开始安装」后会自动跳转到 **任务与日志** 页，实时输出安装过程；完成后自动刷新环境。

### 2. 指定已有路径

如果 Scoop 已装在别处（例如 `D:\scoop`），直接填写该**根目录**。程序会校验目录下是否存在 `apps` 与 `scoop.ps1`，通过后写入应用配置并立即生效。

> 注意填写的是根目录，不是 `apps` 或 `shims` 目录。

### 3. 稍后再说

点击「稍后再说（仅浏览界面）」可关闭向导。此时界面可正常浏览，但所有 Scoop 操作会给出「未安装」的中文提示。后续可随时点顶部的「指定路径」或概览页的「一键安装」重新进入引导。

## 四、各页面操作

### 1. 环境概览

| 区域 | 可做的事 |
| --- | --- |
| 顶部环境卡 | 「重新检测」刷新环境信息；「指定路径」接入已有安装；未安装时显示「一键安装 Scoop」 |
| 指标卡 | 已安装应用数、可更新数、Bucket 数、可搜索应用数、下载缓存体积、已锁定数 |
| 环境体检 | 逐项展示平台、安装、根目录、版本、全局目录、PowerShell、执行策略、配置文件；带复制按钮的项可直接复制路径 |
| 快捷操作 | 环境体检（`scoop checkup`）、更新 Bucket、更新 Scoop 自身、导出 Scoopfile、清理旧版本、清空缓存 |
| 可用更新 | 列出有新版本的应用（当前版本 → 目标版本）与来源 Bucket；行尾可单个更新，右上角「全部更新」批量执行 |

> 「可用更新」需要本地 Bucket 清单是最新的。若列表为空且你确信有更新，先执行一次「更新 Bucket」。

### 2. 已安装应用

- **筛选与排序**：名称搜索、用户 / 全局 / 全部切换、按名称 / 更新时间 / 来源 Bucket 排序；工具栏右侧的「只看可更新」可一键只列出有新版本的应用（按钮上的数字即可更新数量，与用户/全局筛选可叠加使用）。
- **行内操作**（图标）：
  - ⬆ 更新：执行 `scoop update <name>`
  - 🔒 / 🔓 锁定 / 解锁：执行 `scoop hold` / `scoop unhold`，锁定后不会被更新
  - 🔀 重置：`scoop reset`，用于修复 shim 冲突或快捷方式失效
  - 🗑 卸载：带二次确认，默认附加 `-p` 彻底清理
- **批量操作**：勾选若干行后浮出批量工具条，支持批量更新与批量卸载。
- **详情抽屉**：点击应用名打开，展示已安装版本、安装范围、架构、锁定状态、描述、安装路径、命令（shim）、仓库中的版本对比、原始 manifest JSON（可展开）。

### 3. 搜索与安装

- 输入即搜（300ms 防抖），搜索**完全基于本地 Bucket 清单**，不联网、毫秒级返回。
- 顶部「来源 Bucket」下拉可限定范围；右侧显示结果条数、耗时与索引条目数。
- 「重建索引」用于在手动改动 bucket 目录后强制刷新索引。
- 点击某行的「安装」打开右侧安装面板：

| 选项 | 对应参数 | 说明 |
| --- | --- | --- |
| 全局安装 | `-g` | 安装到 `SCOOP_GLOBAL`，需要管理员权限 |
| 独立安装 | `-i` | 不依赖其他应用的共享依赖 |
| 跳过哈希校验 | `-s` | 有安全风险，仅在哈希失效时使用 |
| 不使用缓存 | `-n` | 强制重新下载 |
| 指定架构 | `-a 64bit/32bit/arm64` | 留空为自动 |

面板下方会列出**依赖预览**（含是否已安装 / 是否在本地清单中找不到）与**将执行的命令**，确认无误后点「确认安装」，自动跳转到任务页看实时日志。

### 4. Bucket 管理

- **已添加列表**：名称、仓库来源（非 git 仓库显示「未知」）、清单数、最近更新时间、官方标记。
- **行内操作**：🔍 跳转到搜索页并限定该 Bucket；🔄 更新（对 bucket 目录执行 `git pull`，并自动透传「配置与代理」里的代理）；🗑 删除（二次确认，不会卸载已安装应用）。
- **顶部操作**：「更新全部」与「添加 Bucket」。
- **添加 Bucket 表单**：名称必填（字母数字与 `. _ + -`，须以字母数字开头，不得重复）；仓库地址可留空（使用 Scoop 内置的已知仓库映射），填写时须以 `https://`、`git@`、`ssh://`、`git://` 开头。
- **推荐列表**：官方已知 Bucket 卡片，点一下即添加。优先取 `scoop bucket known` 的结果，取不到时使用内置列表。

### 5. 配置与代理

#### 代理面板

- **保存**：把输入框内容写入 `proxy` 配置（`scoop config proxy <value>`）。
  - 支持 `host:port`、`http://host:port`、`http://user:pass@host:port`，以及内置关键字 `current`（跟随系统）、`none`（关闭）。
  - 格式非法时输入框抖动并显示中文错误。
- **跟随系统**：等价于设置为 `current`。
- **清除**：执行 `scoop config rm proxy`，带二次确认。
- **测试连通性**：对代理地址做一次 TCP 握手探测，返回**延迟毫秒数**或失败原因。仅探测连通性，不发送业务数据。

#### 常用配置

以卡片形式列出高频配置项（aria2 开关、并发下载数、缓存路径等）。布尔型提供开关，其他类型点「设置」即预填到新增表单。卡片右上角标记「已设置」表示当前已有该配置。

#### 全部配置项

- 表格展示键、值、操作。敏感项（如含密码的代理）默认打码，点 👁 可切换显示。
- **新增配置**：键名 + 值。值会按约定做轻量类型推断：`true` / `false` → 布尔，纯整数 → 数字，其余 → 字符串。
- **编辑 / 删除**：所有写入都经由 `scoop config`，由 Scoop 自身完成校验与落盘。

> 底部会显示配置文件路径与是否可写。若显示「不可写」，说明配置文件位于受保护目录，请以管理员身份运行本程序。

### 6. 任务与日志

左侧为任务列表，右侧为实时日志终端。

- **任务列表**：状态色块（排队中 / 执行中 / 成功 / 失败 / 已取消 / 超时）、标题、类型、开始时间、耗时、退出码、目标。
  - 🛑 取消：终止整个进程树（`taskkill /pid <pid> /T /F`）
  - 🔄 重试：失败 / 超时 / 取消的任务可一键重新提交（仅限能还原原始请求的类型）
  - ✕ 删除单条记录
  - 顶部「清理历史」清空所有已结束任务；状态下拉可按状态过滤
- **日志终端**：等宽字体、深色底、行号时间戳、stdout / stderr 分色。
  - 「自动滚动」磁吸到底部（可关闭以便翻阅历史）
  - 「复制」/「下载」导出完整日志文本
  - 日志过长时只渲染末尾 600 行以保证流畅，任务缓冲上限 4000 行，超出会提示「更早的日志已超出缓冲上限被丢弃」
- **连接状态**：顶部与底部都会显示日志流状态（已连接 / 重连中 / 未连接）。断线后会自动按序号补偿重连，**不会丢日志**。

## 五、常见工作流

### 从零开始装一批常用工具

1. 首次引导里「一键安装 Scoop」。
2. 进入 **Bucket 管理**，添加 `extras`、`versions`（推荐卡片一点即加）。
3. 进入 **搜索与安装**，搜索 `7zip` → 安装。
4. 在 **任务与日志** 观察实时输出，完成后再搜下一个。

### 批量升级

1. 概览页点「更新 Bucket」拿到最新清单。
2. 「可用更新」列表核对要升级的项，点「全部更新」。
3. 到任务页观察；如某项卡住可单独取消。

### 遇到网络问题（代理）

1. 进入 **配置与代理**。
2. 输入代理地址 → 「测试连通性」确认延迟正常 → 「保存」。
3. 回到搜索页重新安装/更新。
4. 不需要时代理面板点「清除」。

### 备份与迁移

- 概览页「导出 Scoopfile」下载 JSON 备份（包含已安装应用列表）。
- 在新机器上可通过 `POST /api/scoop/import` 导入（见 [API.md](./API.md)）。

### 释放磁盘空间

1. 概览页「清理旧版本」删除各应用的旧版本目录。
2. 「清空缓存」删除下载缓存（卡片会显示当前占用体积）。

## 六、桌面应用（Windows 客户端）

### 安装

从 `release/` 目录运行 `Scoop Manager_x.y.z_x64-setup.exe`。默认按**当前用户**安装，不需要管理员权限，也不需要预先安装 Node / Bun。

### 与网页版的关系

桌面版用的是同一个后端，功能完全一致（六个页面、实时日志、任务取消都在）。区别只在"怎么把界面和后端连起来"：

- 网页版：后端监听一个端口，浏览器访问 `http://127.0.0.1:3000`
- 桌面版：后端**不监听任何端口**，界面与后端通过进程管道直接通信

因此桌面版**没有**访问地址，也没有「在浏览器中打开」这种入口。

### 托盘

关闭窗口不会退出程序，而是最小化到系统托盘。托盘的右键菜单：

| 菜单项 | 说明 |
| --- | --- |
| 传输：IPC（不占用端口） | 只读状态，用于确认当前运行形态 |
| 显示主界面 | 等同于左键单击托盘图标 |
| 重启服务 | 后端异常时使用，会重启 sidecar 进程 |
| 开机自动启动 | 勾选后随系统登录启动（写入当前用户启动项） |
| 查看日志 | 打开 `%USERPROFILE%\.scoop-manager-desktop\desktop.log` |
| 打开数据目录 | 打开上述目录 |
| 退出 | 先让后端落盘任务历史，再结束进程 |

### 数据目录隔离

| 形态 | 配置与任务历史 |
| --- | --- |
| 网页版 / pm2 / 双击 exe | `%USERPROFILE%\.scoop-manager\` |
| 桌面应用 | `%USERPROFILE%\.scoop-manager-desktop\` |

两套数据互不影响，可以同时运行。注意这意味着**桌面版和网页版的任务历史、程序配置不互通**；Scoop 本身的安装位置是全局的，两边看到的应用列表一致。

### 首次启动

与网页版相同：未检测到 Scoop 时会弹出引导，可以一键安装或指定已有路径。桌面版的引导写入的是 `%USERPROFILE%\.scoop-manager-desktop\config.json`。
